# 读懂 DeepSeek Harness

一个交互式教程工作台，七节课把 DeepSeek Harness 的设计思路讲清楚。面向零基础读者：不需要先懂插件、依赖注入、事件总线，从「大模型只会说话」讲起。

> 内部资料，仅在私有仓库内使用，不要外传或公开部署。
>
> **教程里的代码全部是我们自己写的**，在 `demo/mini-harness/`。不包含任何内测项目的源码、路径、包名或配置格式。这条规则由 `npm run check` 自动把关，违反会直接报错。

## 课程

| | 课程 | 讲什么 |
|---|---|---|
| 01 | Harness 是什么 | 只讲通用概念：模型只会输出文字，谁让它动手 |
| 02 | DeepSeek Harness 是什么 | 框架由哪些部分组成，一次对话怎么流过它们 |
| 03 | 一切皆插件 | 核心设计思想，以及它的好处和代价 |
| 04 | 如何与外界交互 | 接模型、接电脑、接外部工具、接人 |
| 05 | 如何开发插件 | 实操：从零写出一个能跑的插件 |
| 06 | 跟 Claude Code 的区别 | 最本质的那一个差异 |
| 07 | 核心框架 Cordis | 插件机制到底是怎么实现的 |

## 跑起来

```bash
npm install
npm run dev
```

打开 http://localhost:5173 。

| 命令 | 干什么 |
|---|---|
| `npm run dev` | 开发服务器 |
| `npm run demo` | 跑一遍最小 Harness，看真实输出 |
| `npm run build` | 类型检查 + 打包到 `dist/` |
| `npm run typecheck` | 只做类型检查（网页 + demo） |

## 教程里的代码从哪来

全部来自 `demo/mini-harness/`。那是一个我们自己写的、能跑的最小 Harness，约 350 行有效代码，把 Harness 的核心思路用尽可能少的代码演示出来。

```bash
npm run demo
```

跑一下就能看到完整过程：插件排队等依赖、装配、模型要工具、工具执行、危险动作被拦、拒绝理由回灌给模型、插件被拆时自动清理。**教程里「运行记录」面板显示的内容，就是这条命令的真实输出。**

细节看 `demo/mini-harness/README.md`。

## 怎么用

左边是课程目录和进度，右边是工作台。每节课的结构固定：

1. **先打个比方** —— 用生活里的东西讲清这节在说什么
2. **这节课会出现的词** —— 术语的大白话解释，附源码位置
3. **分步演示** —— 左边动画，右边运行记录，下面是代码和解释
4. **容易想错的地方** —— 常见误解，以及源码里其实是怎样
5. **完成检查** —— 两题都答对才算学完，进度存在浏览器本地

分步演示支持上一步、下一步、播放、重置。键盘 `←` `→` 也能翻步，空格播放暂停。

## 怎么加一节课

每节课是一份纯数据，不用写组件。

1. 在 `src/lessons/` 下加一个文件，导出一个符合 `Lesson` 类型的对象
2. 在 `src/lessons/index.ts` 里 import 进来，按顺序放进 `lessons` 数组
3. 跑 `npm run check`

`Lesson` 的字段定义和每个字段的用途，都写在 `src/tutorial/types.ts` 的注释里。

### 数据体检

`npm run check` 查的是类型检查管不到的东西：

- **保密**：课程里有没有出现内测项目的路径、包名、内部函数名、配置格式。这一项是硬拦，一旦命中直接报错。
- 动画点亮的节点和连线，在图里是不是真的存在
- 图上有没有画了却从没点亮过的死线
- 有没有两个节点被放进同一个格子
- 完成检查的正确答案下标有没有越界
- 标签、标题、说明有没有长到画不下或者长到不够浅显

有错误会退出码 1。提醒不会挡住构建，但都值得改。

## 写作约定

- **代码只能来自 `demo/mini-harness/`**。写 `demo/mini-harness/kernel.ts:59` 之前先打开文件确认行号，代码原样复制，最多 14 行。
- **运行记录只能来自 `npm run demo` 的真实输出**，不要编。
- 一句话只讲一件事，超过 30 字就断句。
- 第一次出现的术语先用大白话解释再用。
- 不写营销口号、反问式标题、装饰性英文、emoji。
- 只讲好处不讲代价的内容不要写，那是软文不是教程。
